# slack-cli

An unofficial `slack` binary on PATH for agents and humans, not affiliated
with Slack. Commands are typed Slack Web
API methods generated by an incur plugin from a catalog that a build-time sync
parses out of Slack's own method reference. Login is public PKCE against this
CLI's Slack app through a static HTTPS redirect page that hands the code to
the CLI, and issues long-lived tokens; rotating tokens stored by earlier
versions still refresh themselves. This package
does not wrap Slack's hosted MCP as commands and is not an MCP server.

## Problem and solution

Agents need Slack from the terminal with a stable machine-readable contract.
Slack's hosted MCP returns Markdown blobs (`{ result: "## My Channels..." }`),
which is a chat-agent view, not an automation surface. Slack's official CLI
is an app builder: its developer login cannot read workspace history, and
`slack api` does not use stored credentials as a Web API client.

The Slack Web API (`https://slack.com/api/METHOD`) returns structured JSON
(`ok`, `messages[]`, `channels[]`, `response_metadata.next_cursor`). Slack
publishes no maintained machine-readable spec (the `slack-api-specs` OpenAPI
repository is archived), but every method page on docs.slack.dev has a
Markdown twin with YAML frontmatter and a regular arguments section. A sync
step parses those pages into a committed catalog; an incur plugin turns the
catalog into `slack <family> <method>` with Zod flags and Slack's JSON body as
output.

## Domain model

- **Slack Web API** — `POST https://slack.com/api/{method}` with a user token
  as `Authorization: Bearer` and an `application/x-www-form-urlencoded` body.
  Slack owns method semantics, scopes, and errors.
- **Method reference** — `https://docs.slack.dev/reference/methods.md` (index)
  and `https://docs.slack.dev/reference/methods/{method}.md` (one page per
  method: frontmatter `method_name`, `summary`, `http_method`, `rate_limit`,
  `scopes.{bot,user}`; `## Arguments` with name, type, required/optional,
  description, default, example).
- **Catalog** — `src/catalog.json`, written by `nub run sync-catalog` from the
  method reference. Committed; a sync is a reviewable diff. The CLI never
  reads docs.slack.dev at runtime.
- **Overlay** — `src/overlay.ts`, hand-written facts the catalog does not
  capture: positional arguments for resource ids, mutating methods whose
  scopes do not say `:write`, and help notes for what a reference page states
  only in prose (a retired method and its replacement).
- **incur plugin** — one plugin per top-level family (`conversations`,
  `admin`, …). Remaining name segments are subcommands:
  `users.profile.get` is `slack users profile get`.
- **Workspace credentials** — `~/.config/slack-cli/credentials.json`, mode
  0600, holding `version: 1`, `currentTeamId`, and `teams` keyed by team id.
  Each team entry has `accessToken` and optional `refreshToken`, `expiresAt`
  (epoch milliseconds), `clientId`, and `userId`.
- **Rotating token** — an `xoxe.` access token that expires 12 hours after
  issue and is renewed with its refresh token through
  `oauth.v2.user.access` (`grant_type=refresh_token`). Each refresh revokes
  the previous refresh token. Earlier versions stored these.
- **Long-lived token** — the `xoxp-` token `slack login` stores now: the app
  keeps token rotation off, so it has no refresh token or expiry and lasts
  until revoked. Slack returns the same token to every login by the same user
  in the same workspace, so revoking it signs out every machine that holds it.

## Requirements

- **REQ-PKG-001** Package name `@alleneubank/slack-cli`. PATH binary `slack`.
  Single package. Dependency `@alleneubank/incur`, a fork of `incur` that adds
  root MCP mounts for `mcp: false`, secret env help, call-time skill
  directories, and installs the files beside an included `SKILL.md`.
- **REQ-API-001** Commands are generated from `src/catalog.json`, which covers
  every method in the reference index that a user token can call (its page
  lists user scopes or no scopes), including `admin.*`. Bot-only methods are
  excluded. The `sync-catalog` script regenerates it and fails on a page it
  cannot parse rather than dropping the page or an argument. There is no runtime docs fetch, no local
  reimplementation of Slack method semantics, no MCP `tools/list` mount, and
  no untyped raw-method command.
- **REQ-API-002** Method `a.b.c` is the command `slack a b c`. Flags are
  Slack's argument names verbatim (`--thread_ts`); an argument named like a
  CLI-owned flag (`format`, `schema`, `workspace`, …) is `--slack_<name>`.
  Required arguments are
  required; `boolean`, `integer`, and `number` arguments are validated
  locally; every other type is a string passed through unchanged, except the
  time-range arguments `oldest`, `latest`, `ts_from`, and `ts_to`: they take
  Unix seconds or an ISO 8601 date or date-time (UTC without an offset) and
  send Unix seconds, so agents need no shell date arithmetic. Overlay
  positionals replace their flags. Where the positionals are `<channel> <ts>`
  (`chat delete`, `chat getPermalink`, `chat update`, `conversations
replies`), a single Slack message link
  (`https://<workspace>.slack.com/archives/<channel>/p<ts digits>`) may stand
  for both; `conversations replies` takes the link's `thread_ts` query
  parameter as the thread when present. `conversations history` also takes a
  link for `<channel>` and then reads only that message (`oldest` = `latest` =
  its ts, `inclusive`, `limit` 1) unless any of those four flags is given,
  which then win. A link-shaped value (one containing `/`) that does not
  parse, a missing ts, or a ts given alongside a link fails with
  `INVALID_ARGUMENT` before any request; plain ids are sent unchanged. A local argument parse failure has code
  `INVALID_ARGUMENT`, not `UNKNOWN`. Output is Slack's JSON object, unchanged.
- **REQ-API-003** The request body is form-encoded and contains only the
  catalog's declared arguments for that method. `ok: false` is a command
  error whose code is Slack's `error` string. HTTP 429 is `RATE_LIMITED`,
  retryable, with Slack's `Retry-After` seconds. Any other non-2xx status is
  `HTTP_ERROR`, even when the body parses. A non-JSON body, or a body over
  16 MiB, is `BAD_RESPONSE`. When Slack rejects `SLACK_TOKEN`, including for
  `missing_scope`, the failure says to fix or unset that environment variable
  and does not suggest login, which cannot override it. The token is never
  echoed.
- **REQ-API-004** Without credentials, method commands fail with
  `AUTH_REQUIRED` and do not contact `slack.com`. `--help` and `--version`
  succeed and list `login` plus method families.
- **REQ-API-005** Unit tests inject `fetch`. They never call `slack.com` or
  `mcp.slack.com`.
- **REQ-API-006** Each call returns one Slack page. Output keeps Slack's
  continuation fields (`response_metadata.next_cursor`, `has_more`,
  `paging`). Help for a method with a `cursor` or `page` argument says how to
  request the next page. The CLI does not merge pages or add fields to
  Slack's JSON, except incur's `_warnings` array when a string looks like a
  prompt injection.
- **REQ-API-007** A failure exits 3 when retrying it unchanged may succeed
  (`retryable: true`), 4 when a new `slack login` fixes it (no usable stored
  token, Slack rejected a stored token, an unreadable credentials file, or a
  `missing_scope` that login requests), and 1 otherwise. A rejected
  `SLACK_TOKEN`, including one missing a scope, exits 1 because login cannot
  override it. Exit-4 failures and
  `UNKNOWN_WORKSPACE` carry the command to run as a CTA. A timeout, network
  error, HTTP 5xx, or Slack `internal_error`/`fatal_error`/`service_unavailable`
  is retryable only for methods that do not mutate; for a write it says the
  write may have been applied.
- **REQ-API-008** The CLI collects no data. It contacts only `slack.com`: no
  analytics, telemetry, or background update check (create-level `update` is
  `false`). `slack --update` contacts the npm registry only when run.
- **REQ-MCP-002** This CLI does not present itself as an MCP server:
  create-level `mcp` is `false`, and README does not tell users to run
  `mcp add` or `--mcp` on `slack`. `slack skills add` installs one
  hand-written skill, `skills/slack/` (`SKILL.md` and the reference files it
  links), in place of incur's generated skills.
- **REQ-AUTH-001** The token comes from `SLACK_TOKEN`, else from the stored
  workspace selected by `--workspace`, else `SLACK_WORKSPACE`, else
  `currentTeamId`. Never from a flag: `--token` is rejected. A named workspace
  that is not stored is `UNKNOWN_WORKSPACE`, listing the stored team ids. An unreadable or malformed
  credentials file is `CREDENTIALS_INVALID`.
- **REQ-AUTH-002** Command output and errors never echo an access token,
  refresh token, client secret, or authorization code. Root `--help` lists
  `SLACK_TOKEN`, `SLACK_WORKSPACE`, and `SLACK_CLIENT_ID`; a set `SLACK_TOKEN`
  shows only `(set)`.
- **REQ-AUTH-003** `slack login` authorizes with public PKCE using the packaged
  client id, overridable with `SLACK_CLIENT_ID`. Never argv. The Slack app sets
  `pkce_enabled: true`, `token_rotation_enabled: false`, and registers only the
  HTTPS redirect `https://alleneubank.github.io/slack-cli/callback/` (Slack
  requires HTTPS redirects to distribute an app). Token exchange sends that
  redirect and no client secret. The OAuth state is `loopback.<random>` or,
  with `--paste`, `paste.<random>`. The redirect page (`docs/callback/`)
  forwards only `code`, `state`, and `error`, and only to
  `http://127.0.0.1:8912/callback`, for a `loopback.` state; shows the code
  for a `paste.` state, then removes it from the address bar; and otherwise
  shows install instructions. The loopback listener ignores callbacks whose
  state does not match the active login and keeps waiting for the matching
  callback until its deadline. With `--paste` the CLI prints the authorize URL
  before prompting, reads the code from the terminal, rejects text that is
  not code-shaped without echoing it, and does not listen on a port.
- **REQ-AUTH-004** `slack login` adds or replaces the authorized workspace,
  records its client id and expiry, and makes it current; other workspaces are
  kept. `slack logout` removes the selected workspace and, when others remain,
  makes the lowest remaining team id current and reports it. `slack logout
--all` removes every workspace. A legacy single-object credentials file is read as one
  team and rewritten in the versioned format on the next write. Writes are
  atomic (temp file, then rename) at mode 0600.
- **REQ-AUTH-005** A stored workspace with a refresh token is refreshed before a
  call when it expires within 5 minutes, and once after Slack answers
  `token_expired`. Refresh runs under an exclusive lock on the credentials
  file, re-reads the file after taking the lock, and persists the new tokens
  before using them. A failed refresh is `AUTH_EXPIRED` ("run slack login").
  `SLACK_TOKEN` is never refreshed.
- **REQ-AUTH-006** Login and refresh record the user scopes Slack reports
  (which accumulate across logins) and the team name. `slack workspaces list`
  shows each stored workspace (team id and name, user id, whether it is
  current, whether it rotates, access token expiry, and with `--scopes` the
  scopes) and whether `SLACK_TOKEN` overrides them, without printing tokens.
  Scopes are opt-in because they are most of the output (about 60 per
  workspace) and a `missing_scope` error already names the scope it needs. `slack workspaces use
<team>` makes a stored workspace current.
- **REQ-TEST-001** Unit tests assert observable CLI output against injected
  OAuth and Web API `fetch` for cases the live workspace cannot produce on
  demand (HTTP errors, rate limits, oversize bodies, secret redaction,
  credential migration, refresh races). Slack behavior (request encoding,
  arguments, pagination, refresh) is verified against a live test
  workspace. The catalog parser is tested against real method reference
  pages.

## Invariants

- Slack's Web API JSON is the source of truth for method results.
- Tokens never appear in argv, committed files, fixtures that are real
  credentials, or command output.
- Unit tests do not use the network.
- Pagination stays Slack's; this CLI does not pretend a page is the full
  collection.
- A refresh token is used at most once; the credentials file never holds a
  revoked refresh token after a successful refresh.

## Non-goals

- Mounting Slack's hosted MCP as CLI commands.
- Serving this CLI as an MCP server for other agents.
- Fetching docs.slack.dev at runtime.
- An untyped `slack api <method>` escape hatch.
- Auto-pagination or merged multi-page output.
- Creating the Slack app. `slack login` runs user OAuth once it exists.
- Inventing fields Slack did not return.

## Decisions

- Package `@alleneubank/slack-cli`, bin `slack`. Unscoped `slack-cli` is taken
  on npm. The bin shares its name with Slack's official CLI; README and help
  say this CLI is unofficial.
- **Withdrawn:** reuse Slack's hosted MCP as the command source. MCP returns
  Markdown `result` strings; that is not an automation contract. Official
  `slackapi/slack-cli` is an app builder and a dead end for reading workspace
  history.
- The catalog is generated at build time from docs.slack.dev method Markdown
  into a committed file, covering all methods including `admin.*`, with no
  raw fallback command.
- Rotating tokens are refreshed by the CLI. Slack issues `xoxe.` user tokens
  with a refresh token although the manifest says
  `token_rotation_enabled: false`.
- Pagination is one Slack page per call; continuation is documented in help,
  not injected into output (incur merges a CTA into agent-mode data).
- Slack user OAuth (public PKCE) is unchanged; the token is a Web API user
  token, not an MCP session.
- Request bodies are form-encoded for every method: every reference page
  lists form encoding, and the Web API overview limits JSON bodies to some
  write methods.
- `mutates` comes from a `:write` scope plus the overlay; it injects
  `--dry-run`.
- Logout of the current workspace switches to the lowest remaining team id and
  reports it, following `gh auth logout`.
- The workspace selector is `--workspace` / `SLACK_WORKSPACE`, not `--team`:
  `team.info` takes a Slack argument named `team`, and a global `--team` would
  swallow it.
- Bot-only methods (36 of 324: datastore, assistant threads, streams, shared
  invites, workflow trigger permissions) are excluded; a user token cannot call
  them.
- `search:read` is a requested read scope: `search.messages` needs it and the
  granular `search:read.*` scopes do not grant it (a live `missing_scope`
  named `search:read`). The Slack Marketplace does not allow `search:read`,
  so the app is publicly distributed but not listed there, and Slack caps
  `conversations.history` and `conversations.replies` for its new installs.
- `slack skills add` installs one hand-written skill instead of incur's
  generated ones: generated at depth 0 it is one 324 KB file, at depth 1 it is
  37 skills with a 124 KB `admin` skill. The skill teaches discovery
  (`--help`, per-family `--llms-full`) instead of listing methods, and keeps
  `SKILL.md` short. The reads most tasks start with (message links, date
  ranges, search, lookups by name) are in `SKILL.md`, because a reference
  read costs an agent a turn on nearly every task; write flows and file
  handling live in `skills/slack/references/`, which agents read on demand.
- incur's prompt-injection scan stays on and may add `_warnings` to Slack's
  JSON: agents reading other people's messages need the signal more than
  byte-for-byte output.
- The bin entry exports nothing, enforced by oxlint
  `import/no-default-export` under `src/`: Bun serves a default export that
  has `fetch` over HTTP, which would expose every Slack method with the stored
  credentials.
- A method is `destructive` when its verb is archive, delete, disconnect,
  invalidate, kick, reset, revoke, or uninstall, or when it is an admin
  `remove*`; the reference does not say. Argument examples go in each
  argument's description rather than generated example commands, which would
  omit arguments the docs mark optional but a call needs (`text` for
  `chat.postMessage`).
- Local `slack-app-manifest.yaml` is the Slack app source of truth and lists
  exactly the scopes login requests. Login requests every user scope a catalog
  method accepts that Slack lets a distributed app request in a standard
  workspace: plain `slack login` requests only scopes no state-changing method
  accepts, and `slack login --write` adds the rest. Left out: `admin.*`
  (Enterprise organizations only), `admin` (only admin installers can grant
  it, and it also grants the SCIM API), `app_configurations:write` and
  `hosting:read` (the app manifest rejects them as user scopes), and
  `client`, `identity:read`, `openid`, and `tokens.basic` (Slack refuses the
  request with them).

## Risk tags

- **Auth:** env/login token forwarded to Slack Web API; credential file format
  and refresh-token rotation. Changes here get a security review.
- **Public API:** `slack` binary surface; commands come from the generated
  catalog.
